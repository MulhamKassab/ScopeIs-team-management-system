# Cover workspace and access amendment — 2026-10-15

## Confirmed product direction

The owner authorized implementation and a push to main. Cover combines finding support and managing requests on one page at `/coverage`. `/replacements` redirects to its Current requests section. This amendment supersedes older Admin access to unpublished schedules, team leave and reports, and older Admin project-creation authority. Authority follows the stored system role, never a person's name or job title.

- Cover copies the currently authorized timetable with Month, People and Agenda views. Selecting a cell opens assignment facts and a Request cover action. A Create request button is visible at the page heading and above Current requests. Pending requests use an amber treatment and a text label; approved changes awaiting publication use green and a Draft label. Colour is supplementary.
- A replacement can be requested for any currently visible assignment, including one without a recorded staffing or qualification gap. Extra support remains tied to a current staffing shortage. Existing skills, availability, duplicate-request, overlap, stale-work and transactional approval checks remain binding.
- Super Admin may create requests for Draft, Proposed or current Published assignments. Admin requests begin only from current Published assignments within both TEAM and operational scope. Admin reads never expose a copied Draft, its identifiers, notes or schedule data through timetable, cover, reports or discussions.
- Pending requests may be edited or cancelled by their requester or Super Admin. Editing changes the proposed covering person and rechecks current eligibility. Changing the assignment or request type requires cancellation and a new request. Cancellation removes the request from the active queue and preserves history; it does not change a schedule. Completed decisions cannot be edited/cancelled. Updates use row locks, expected versions and atomic audit writes.
- The existing database closed state `REJECTED` with a null `decided_by_user_id` and a populated `decided_at` represents a withdrawal, displayed as Cancelled. An actual rejection always records its Super Admin decision-maker. Distinct `coverage.replacement_cancelled` and `coverage.replacement_edited` audit events preserve meaning. This compatibility representation requires no migration and never deletes request/discussion records.
- Super Admin reviews directly on the request card: select the covering person and Approve cover, or Reject request without a person. Approval prepares or updates a Draft. Publication remains a separate Super Admin step; current Published work is immutable until a revision is published. Approved request presentation reads the actual effect-period lifecycle: Draft/Proposed keeps the pending-publication marker and link; Published removes that marker/link and shows Schedule published, including after supersession. An unavailable effect uses neutral Approved. There is no stored publication flag or migration.
- Only Super Admin sees unpublished timetables, team leave and report pages/exports, creates clients/projects, and creates/edits assignments. Admin keeps scoped current Published timetable reads, cover requests, the privacy-filtered work map and existing authorized operational maintenance. Employee keeps their own Published timetable and their own vacation submission, cancellation, balance and history. Team-leave information is omitted from the Admin dashboard/map; internal availability checks still use approved leave.
- Main Timetable exposes Create assignment directly. It selects a monthly Draft, person, project, linked worksite, date and time. A selected calendar date is carried into the form. Existing create-Draft and revision/proposal/publication controls remain explicit.
- Work map adds readable place labels, double-click zoom, selected-assignment context and Previous/Next assignment controls linked to map focus. Coverage flags on the map are evaluated against the displayed current Published work, so an unpublished cover revision cannot break the map or leak its changes. Map pan, zoom, layers, keyboard access, touch scroll locking, tile failure fallback and provider attribution remain. Stored exact/coarse coordinate rules, authorized projection and no-live-tracking policy remain binding.

## Architecture and presentation

Use the existing modular monolith, services/repositories, Server Actions and native task dialogs. There is no new provider, authentication mechanism, background service or database migration. Preserve 44px controls, internal timetable scrolling, phone reflow, logical RTL positioning, both themes, forced colours, reduced motion, modal focus/Escape and visible success/stale-write feedback.

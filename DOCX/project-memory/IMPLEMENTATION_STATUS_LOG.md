## 2026-09-18 — Super Admin account and credential management remediation (R1)

Added the Super Admin-only account-administration journey (`/accounts` plus `/account/change-password`). A currently active Super Admin can create an application account together with its workforce profile atomically, enable sign-in for an existing workforce record, and reset passwords. Existing passwords are one-way scrypt hashes and can never be viewed or recovered; the UI states this and offers a temporary-password reset. Password reset uses a fresh salt, clears lock state and failed attempts, increments the credential version and the target's `session_version`, revokes all of the target's sessions, and writes one content-free audit event. `must_change_password` is enforced from PostgreSQL in the protected layout so a temporary-password user must change it before entering the application. Authorization is enforced independently at the navigation, page, service, and Server Action layers, and every mutation re-reads the acting user inside its transaction; Admin, Employee, inactive, and demoted actors receive a non-enumerating refusal. Added the additive migration `0013_super_admin_account_management.sql` (33 public tables retained; 14-migration ledger), a focused `src/modules/account-administration/` module, and new audit actions `auth.account.created`, `auth.credentials.enabled`, `auth.password.reset`, and `auth.password.changed`. Production remains `BLOCKED` on the same prerequisites as the credential remediation (`AUTH_PASSWORD_PEPPER` unset; Production database target, migration state, and recovery point unverifiable), so no Production migration, bootstrap, or deployment was performed. No Phase 12 work was started; the Preview worktree, prototype, historical remediation script, and `.env*` files were left untouched.
